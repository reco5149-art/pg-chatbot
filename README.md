# 피지컬그라운드 안내 챗봇 (브라우저 RAG)

경기 용인의 크로스핏·기능성 트레이닝 센터 **피지컬그라운드**에 처음 오려는 사람이 체험 비용, 이용 요금, 수업 시간표, 위치·주차, 등록·홀딩 규정을 물으면, 센터가 공개한 자료와 운영자가 확인한 정보에서 근거를 찾아 **출처와 함께** 답하는 챗봇이다. 자료에 없는 것은 넓혀 답하지 않고 "제가 가진 자료에는 없습니다"라고 밝힌 뒤 센터 문의를 안내한다. 몸 상태 판단, 할인·환불·예약 확정은 하지 않는다.

- **배포 주소**: https://reco5149-art.github.io/pg-chatbot/
- **제품 약속과 범위**: [PRD.md](PRD.md)
- **자료 원문**: [docs/center-guide.md](docs/center-guide.md)
- **구조**: 모두의연구소 「모두콘 안내 챗봇」 참조 구현을 그대로 쓰고 자료·문구만 교체

## 사용 조건 (먼저 읽어 주세요)

이 페이지는 정적 페이지다. **답변은 페이지를 연 사람의 브라우저와 그 사람 컴퓨터의 Ollama가 만든다.** 아래 조건이 없으면 페이지는 열려도 답이 나오지 않는다.

1. 배포 주소를 열고 이 챗봇이 다루는 자료와 질문을 읽는다.
2. 내 컴퓨터에서 Ollama를 실행하고 `qwen3.5:2b`를 준비한다 (`ollama pull qwen3.5:2b`).
3. 첫 질문 때 임베딩 모델(약 200MB)을 내려받으므로 기다린다. 이후에는 브라우저에 캐시된다.
4. 배포 주소에서 쓰려면 `OLLAMA_ORIGINS`에 `https://reco5149-art.github.io`를 허용하고 Ollama를 다시 켠 뒤, 안내한 질문과 자료 밖 질문을 각각 입력한다. Chrome·Edge를 쓴다.

**Windows에서 4번 하는 법**: 작업 표시줄에서 Ollama 종료 → 설정에서 "환경 변수" 검색 → "계정의 환경 변수 편집" → 새로 만들기: 이름 `OLLAMA_ORIGINS`, 값 `https://reco5149-art.github.io` → 확인 → Ollama 다시 실행. (내 PC의 개발 서버 `localhost`에서 열 때는 필요 없다.)

연결이 안 되면 페이지 위에 원인별 안내(Ollama 꺼짐·모델 없음·CORS)와 **다시 확인** 버튼이 나온다.

## 설계 결정 요약

| 결정 | 이유 |
|---|---|
| 자료는 센터가 공개한 화면(플레이스·카페 시간표 공지) + 운영자 확인 정보 18조각만 | 답의 근거를 사용자가 직접 열어 볼 수 있어야 믿을지 판단할 수 있다. 회원 정보·후기는 넣지 않는다 |
| 청크 스키마 `id, text, url, section, vector`와 검색·프롬프트 파이프라인은 모두콘 그대로 | 바뀐 결과를 **내 자료의 차이**로 읽기 위해서. 바꾼 것은 자료, 자료 소개 문장, 시스템 메시지의 도메인 규칙, 화면 문구뿐이다 |
| 문서 벡터를 질문과 같은 브라우저 함수(`embed`, `model_no_gather_q4`)로 생성 | 모델·파일·후처리가 같아야 768차원 점수를 비교할 수 있다. 개발용 `/embed.html`이 이 일을 한다 |
| 운영자 확인 정보의 출처 링크는 이 저장소의 원문 문서 절로 | 공개 웹 주소가 없는 사실도 근거를 열어 볼 수 있게 하고, 누가 언제 확인했는지 남긴다 |
| 자료 밖·몸 상태·약속 요구에 고정 안내 문구 | 거절을 줄이는 장치가 아니라 답변의 경계를 사용자에게 알리는 약속. 틀린 가격 하나가 거절 열 번보다 신뢰를 더 잃게 한다 |
| Ollama 연결 확인에 모델 존재 여부를 추가 | 서버는 켜졌는데 모델이 없을 때, 사용자가 원인을 구별할 수 있게 |

## 실행 (내 PC, 개발 서버)

```powershell
cd app
npm install
npm run dev          # http://localhost:5173
```

또는 `scripts\dev.ps1`이 Node·Ollama·모델 확인, 설치, 개발 서버 실행, 크롬 열기를 한 번에 한다.

### 자료 벡터 만들기 / 자료 갱신

1. 자료가 바뀌면 `docs/center-guide.md`와 `app/data/pg-chunks.json`을 함께 고친다(같은 `section`, 새 사실은 다음 id).
2. 개발 서버에서 `http://localhost:5173/embed.html` → **벡터 만들기 시작**.
   - 챗봇의 질문 임베딩과 같은 경로로 18개 청크를 768차원으로 바꿔 `app/public/pg-docs.json`에 저장한다.
   - 저장 전에 스키마(`id, text, url, section, vector`), id 형식, 중복, 768차원을 검사한다.
   - 저장 뒤 확인 질문 3개의 검색 상위 3개를 보여 준다.
3. `app/public/pg-docs.json`을 커밋하고 푸시하면 배포에 반영된다.

## 배포

`main`에 푸시하면 `.github/workflows/deploy.yml`이 `app`을 `npm run build`하고 `app/dist`를 GitHub Pages에 올린다(`vite.config.ts`의 `base: './'`로 하위 주소에서도 자산을 찾는다). 처음 한 번은 `scripts\deploy.ps1`이 저장소 생성, 푸시, Pages 설정(GitHub Actions)을 한다.

**배포 확인 절차** (주소가 열리는 것만으로 끝내지 않는다)

| 확인 | 방법 | 결과 |
|---|---|---|
| 자산 로드 | 배포 주소 첫 화면, 개발자 도구 콘솔에 오류 없음 | |
| 모델 연결 | 사용 조건 4번 후 "ollama 연결됨" 표시 | |
| 출처 표시 | "체험 수업 비용이 얼마예요?" → 답에 `[PG-013]`, 출처 칩, 원문 링크 | |
| 거부 안내 | "내일 날씨 어때?" → "제가 가진 자료에는 없습니다…" + ⚠ 약한 근거 배지 | |
| 실패 안내 | Ollama를 끄고 새로고침 → 연결 실패 안내와 다시 확인 버튼 | |

## 실험 결과

## 한계

- 답변 품질은 사용자 PC의 `qwen3.5:2b`에 달려 있다. 2B 모델은 시스템 메시지 규칙을 모두 지키지 못할 수 있어, 실험으로 확인하고 기록한다.
- 시간표는 카페 공지 이미지에서 옮긴 것이다. 칸이 합쳐진 부분(수·금 낮 시간)은 원본과 대조했다는 확인을 운영자가 남겨야 한다.
- 영업시간이 운영자 확인값(평일 22:30)과 네이버 플레이스 화면(23:00 종료)에서 다르다. 챗봇은 운영자 확인값을 쓰고, 플레이스를 맞출 예정이다.
